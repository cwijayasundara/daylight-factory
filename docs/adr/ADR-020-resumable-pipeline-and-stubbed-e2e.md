# ADR-020: Resumable pipeline with phase checkpoints, and a stubbed end-to-end test

**Status** accepted (task 1 of the plan in docs/analysis/deep-dive-fable-5-2.md). **Context** Seven live brownfield attempts cost 79 min and $22.80; every retry restarted from design and regenerated a different spec and plan, and `runPipeline` had no test, so each harness fix was verified by a live 8-21 minute run. **Decision** (1) `plugin/tests/pipeline.test.ts` runs the whole pipeline (triage, ingest, design, Gate 1, plan, parallel tasks, sensors, trace, scope, judge, reviews, PR, Gate 2, merge, wiki, deploy, smoke) against a fixture repo with a scripted `claude`, `docker` and no remote; it completes in about 4 seconds. (2) `daylight run` writes `.daylight/run-state.json` (run id, base, SHA-256 of PRD+base, completed phases, passed tasks). `--resume` skips completed design (only if the Gate 1 hashes still match), plan and inner phases and re-runs only unfinished tasks, reattaching to their existing branches; a changed PRD or base discards the checkpoints; an existing run branch without `--resume` is refused with a clear message. `--stop-after design|plan|inner` stops at a checkpoint. **Consequences** a retry after a late failure costs seconds and no model calls for completed phases (measured by call counts in the tests: zero design, gate or plan calls after resume; zero generator calls after an inner-complete resume; exactly one generator call to redo one escalated task). Checkpoints are coarse: resume mid-fix-round re-runs the checks. The stub encodes the role contracts (prompts, JSON shapes), so a change to a prompt contract must update the stub.
